# Анализ расширений iCalendar (RFC 7986, 7953, 9073, 9253, 9074, 7529)

В данном документе представлен анализ шести ключевых RFC, расширяющих базовую спецификацию iCalendar (RFC 5545). Эти расширения направлены на улучшение описания календарей, управление доступностью, публикацию сложных событий, управление взаимосвязями между компонентами, расширение напоминаний и поддержку негригорианских календарей.

---

## 1. RFC 7986: Новые свойства для данных iCalendar

**Дата публикации:** Октябрь 2016
**Статус:** Standards Track

Этот RFC вводит ряд новых свойств, которые в основном относятся к самому объекту `VCALENDAR`, а также расширяет использование некоторых существующих свойств.

### Ключевые нововведения:
*   **Свойства на уровне VCALENDAR**:
    *   `NAME`: Текстовое название календаря (например, "Рабочий график").
    *   `DESCRIPTION`: Более подробное описание назначения календаря.
    *   `REFRESH-INTERVAL`: Рекомендуемый интервал обновления данных клиентом.
    *   `COLOR`: Рекомендация по цвету для отображения календаря в интерфейсе (формат CSS3 color name или шестнадцатеричный код).
    *   `SOURCE`: URI, указывающий на источник данных календаря.
*   **Расширение контекста**: Свойства `UID`, `LAST-MODIFIED`, `URL`, `CATEGORIES` и `IMAGE` теперь могут применяться не только к событиям (`VEVENT`), но и к самому `VCALENDAR`.
*   **Свойство IMAGE**: Позволяет привязывать графические изображения (иконки, баннеры) к календарю или событию через URI или inline-данные.

## 2. RFC 7953: Доступность календаря (VAVAILABILITY)

**Дата публикации:** Август 2016
**Статус:** Standards Track

RFC 7953 вводит новый компонент `VAVAILABILITY`, предназначенный для описания периодов доступности (или занятости) пользователя или ресурса. Это значительно гибче, чем стандартный `VFREEBUSY`.

### Ключевые аспекты:
*   **Компонент VAVAILABILITY**: Действует как контейнер для определения "окон" доступности.
*   **Подкомпонент AVAILABLE**: Определяет конкретный интервал времени, в который ресурс доступен.
*   **Рекурсия**: Поддерживает `RRULE`, что позволяет описывать повторяющиеся графики (например, "каждый понедельник с 9:00 до 18:00").
*   **Логика**: По умолчанию всё время, охваченное `VAVAILABILITY`, считается занятым (BUSY), если оно явно не помечено как `AVAILABLE`.
*   **Интеграция**: Плотно взаимодействует с CalDAV для вычисления свободного/занятого времени при планировании встреч.

## 3. RFC 9073: Расширения для публикации событий

**Дата публикации:** Август 2021
**Статус:** Standards Track

Этот RFC значительно расширяет возможности iCalendar по описанию метаданных событий, делая его пригодным для социальных сетей и сложных публикаций.

### Ключевые нововведения:
*   **STRUCTURED-DATA**: Позволяет внедрять структурированные данные (например, JSON-LD в формате schema.org) непосредственно в календарный объект. Это упрощает автоматическую обработку данных роботами и поисковиками.
*   **Новые компоненты**:
    *   `PARTICIPANT`: Более детальное описание участников (не только `ATTENDEE`), включая тип участия, роль и ссылки на социальные профили.
    *   `LOCATION`: Расширенное описание мест проведения с поддержкой координат, адресов и ссылок на внешние карты.
    *   `RESOURCE`: Описание материальных или информационных ресурсов, необходимых для события.
*   **Стилизованные описания**: Свойство `STYLED-DESCRIPTION` позволяет передавать форматированный текст (HTML), дополняя стандартное текстовое описание.

## 4. RFC 9253: Поддержка взаимосвязей в iCalendar

**Дата публикации:** Июль 2022
**Статус:** Standards Track

RFC 9253 (обновляющий некоторые аспекты RFC 5545) фокусируется на механизмах связывания компонентов и группировки данных.

### Ключевые аспекты:
*   **Новые свойства**:
    *   `LINK`: Позволяет связывать календарный компонент с внешними ресурсами (веб-страницы, документы, связанные календари) через URI. В отличие от `URL`, поддерживает типы отношений и медиа-типы.
    *   `CONCEPT`: Позволяет классифицировать компоненты по семантическим категориям (например, "деловая встреча", "личный досуг") через URI.
    *   `REFID`: Уникальный идентификатор ссылки для отслеживания связей.
*   **Расширение RELATED-TO**: Введены новые типы отношений, позволяющие строить сложные иерархии и сетевые связи между задачами и событиями.
*   **Гибкость**: Эти инструменты позволяют создавать распределенные системы календарей, где события на одном сервере могут ссылаться на детали, хранящиеся на другом.

## 5. RFC 9074: Расширения VALARM

**Дата публикации:** Август 2021
**Статус:** Standards Track

RFC 9074 расширяет компонент `VALARM`, добавляя поддержку подтверждения напоминаний и proximity‑триггеров.

### Ключевые аспекты:
*   **ACKNOWLEDGED**: фиксирует момент подтверждения напоминания.
*   **RELATED-TO;RELTYPE=SNOOZE**: связь «отложенного» напоминания с исходным.
*   **PROXIMITY**: задаёт триггеры по месту (ARRIVE/DEPART/CONNECT/DISCONNECT).
*   **VLOCATION**: подкомпоненты локаций, используемые proximity‑триггерами.

---

## 6. RFC 7529: Негригорианские RRULE

**Дата публикации:** Май 2015
**Статус:** Standards Track

RFC 7529 добавляет поддержку негригорианских календарных шкал в RRULE.

### Ключевые аспекты:
*   **RSCALE**: выбор календарной шкалы (например, `HEBREW`, `ISLAMIC`, `CHINESE`).
*   **SKIP**: стратегия обработки несуществующих дат (`OMIT`, `BACKWARD`, `FORWARD`).
