# Анализ RFC 5545: компоненты VTODO и VJOURNAL

Документ дополняет `ical_analysis.md` и описывает два компонента iCalendar,
не охваченные в основном анализе VEVENT.
Источник: RFC 5545 §3.6.2 (VTODO) и §3.6.3 (VJOURNAL).

---

## VTODO (§3.6.2) — задача / to-do

### Назначение

`VTODO` представляет задачу из списка дел («to-do»), которую необходимо выполнить
(например, сдать отчёт, опубликовать черновик). Компонент может содержать
вложенные `VALARM` — как и `VEVENT`.

### Обязательные свойства

| Свойство    | Описание                                      |
|-------------|-----------------------------------------------|
| `UID`       | Глобально уникальный идентификатор.           |
| `DTSTAMP`   | Временная метка создания объекта iCalendar.   |

### Опциональные свойства (не более одного вхождения)

| Свойство           | Тип              | Описание                                                      |
|--------------------|------------------|---------------------------------------------------------------|
| `DTSTART`          | DATE / DATE-TIME | Дата начала задачи.                                           |
| `DUE`              | DATE / DATE-TIME | Срок выполнения (дедлайн). **Взаимоисключает `DURATION`.**    |
| `DURATION`         | DURATION         | Длительность задачи. Требует `DTSTART`. Взаимоисключает `DUE`.|
| `COMPLETED`        | DATE-TIME (UTC)  | Дата и время фактического выполнения.                         |
| `PERCENT-COMPLETE` | INTEGER (0–100)  | Процент готовности задачи.                                    |
| `PRIORITY`         | INTEGER (0–9)    | Приоритет: 0=не задан, 1=высший, 9=низший.                   |
| `SUMMARY`          | TEXT             | Краткое название задачи.                                      |
| `DESCRIPTION`      | TEXT             | Подробное описание.                                           |
| `LOCATION`         | TEXT             | Место выполнения.                                             |
| `URL`              | URI              | Связанная ссылка.                                             |
| `STATUS`           | TEXT             | `NEEDS-ACTION`, `IN-PROCESS`, `COMPLETED`, `CANCELLED`.       |
| `CLASS`            | TEXT             | Уровень доступа: `PUBLIC`, `PRIVATE`, `CONFIDENTIAL`.         |
| `ORGANIZER`        | CAL-ADDRESS      | Организатор / постановщик задачи.                             |
| `SEQUENCE`         | INTEGER          | Порядковый номер ревизии.                                     |
| `RECURRENCE-ID`    | DATE-TIME        | Идентификатор экземпляра повторяющейся задачи.                |
| `CREATED`          | DATE-TIME (UTC)  | Дата создания компонента.                                     |
| `LAST-MODIFIED`    | DATE-TIME (UTC)  | Дата последнего изменения.                                    |
| `GEO`              | FLOAT;FLOAT      | GPS-координаты места выполнения.                              |

### Опциональные свойства (допускают несколько вхождений)

`RRULE` (рекомендуется не более одного), `RDATE`, `EXDATE`, `ATTENDEE`,
`RELATED-TO`, `ATTACH`, `CATEGORIES`, `COMMENT`, `CONTACT`, `X-*`.

### Вложенные компоненты

`VTODO` **может** содержать вложенные `VALARM` (аналогично `VEVENT`).

### Ключевые отличия от VEVENT

| Аспект              | VEVENT              | VTODO                             |
|---------------------|---------------------|-----------------------------------|
| Конечное время      | `DTEND`             | `DUE`                             |
| Завершение          | нет                 | `COMPLETED` (реальный факт)       |
| Готовность          | нет                 | `PERCENT-COMPLETE`                |
| Приоритет           | нет                 | `PRIORITY`                        |
| VALARM              | да                  | да                                |
| Без DTSTART/DUE     | некорректно         | задача «без дедлайна» — допустимо |

### Нюансы реализации парсера

1. **`DUE` vs `DURATION`**: оба опциональны, но не одновременно. При наличии
   `DURATION` поле `DTSTART` обязательно.
2. **`PRIORITY`** — целое 0–9. Семантика: 1-4 = высокий, 5 = средний, 6-9 = низкий;
   0 = приоритет не определён.
3. **`PERCENT-COMPLETE`** — значение от 0 до 100 включительно.
4. **`STATUS`** для VTODO имеет отдельное множество значений, не совпадающее с
   `VEVENT` (нет `TENTATIVE`/`CONFIRMED`, есть `IN-PROCESS`).
5. **Задача без сроков** (`DTSTART` и `DUE` отсутствуют) — допустима по RFC;
   трактуется как повторяющаяся ежедневно до выполнения.

## VJOURNAL (§3.6.3) — запись в журнале / дневнике

### Назначение

`VJOURNAL` — это текстовые заметки, привязанные к конкретной календарной дате.
Примеры: протоколы заседаний, журнал звонков, список достижений за день.
Компонент **не занимает время** в календаре и прозрачен для поиска занятости
(эквивалентен `TRANSP:TRANSPARENT`).

### Обязательные свойства

| Свойство    | Описание                                      |
|-------------|-----------------------------------------------|
| `UID`       | Глобально уникальный идентификатор.           |
| `DTSTAMP`   | Временная метка создания объекта iCalendar.   |

### Опциональные свойства (не более одного вхождения)

| Свойство        | Тип              | Описание                                         |
|-----------------|------------------|--------------------------------------------------|
| `DTSTART`       | DATE / DATE-TIME | Дата записи (обычно `VALUE=DATE`).               |
| `SUMMARY`       | TEXT             | Заголовок записи.                                |
| `STATUS`        | TEXT             | `DRAFT`, `FINAL`, `CANCELLED`.                   |
| `CLASS`         | TEXT             | Уровень доступа.                                 |
| `ORGANIZER`     | CAL-ADDRESS      | Автор записи.                                    |
| `SEQUENCE`      | INTEGER          | Порядковый номер ревизии.                        |
| `RECURRENCE-ID` | DATE-TIME        | Идентификатор экземпляра повторяющейся записи.   |
| `CREATED`       | DATE-TIME (UTC)  | Дата создания компонента.                        |
| `LAST-MODIFIED` | DATE-TIME (UTC)  | Дата последнего изменения.                       |
| `URL`           | URI              | Связанная ссылка.                                |

### Опциональные свойства (допускают несколько вхождений)

`DESCRIPTION` (**множественный — важно!**), `RRULE` (обычно не более одного),
`RDATE`, `EXDATE`, `ATTENDEE`, `RELATED-TO`, `ATTACH`, `CATEGORIES`, `COMMENT`,
`CONTACT`, `X-*`.

### Ключевые отличия от VEVENT и VTODO

| Аспект              | VEVENT  | VTODO   | VJOURNAL      |
|---------------------|---------|---------|---------------|
| Занимает время      | да      | да      | **нет**       |
| DTEND / DUE         | DTEND   | DUE     | **нет**       |
| PRIORITY            | нет     | да      | **нет**       |
| COMPLETED           | нет     | да      | **нет**       |
| VALARM              | да      | да      | **нет**       |
| Несколько DESCRIPTION | нет   | нет     | **да**        |
| STATUS values       | TENT/CONF/CANC | NA/IP/COMP/CANC | DRAFT/FINAL/CANC |

### Нюансы реализации парсера

1. **`DESCRIPTION` — множественный**: каждая строка `DESCRIPTION` является
   отдельным текстовым блоком. В модели следует хранить `[]string`, а не `string`.
2. **Нет `VALARM`**: вложенные напоминания запрещены стандартом.
3. **`DTSTART` обычно `VALUE=DATE`**: запись чаще привязана к дате, не к времени.
4. **`STATUS`** для VJOURNAL: `DRAFT` (черновик), `FINAL` (финальная версия),
   `CANCELLED` (нейтрально для поиска занятости).
5. **Прозрачен для free/busy**: VJOURNAL никогда не влияет на статус занятости.

## Связи между компонентами

Компоненты могут ссылаться друг на друга через `RELATED-TO`:

```
VEVENT  <--RELATED-TO-->  VTODO
VEVENT  <--RELATED-TO-->  VJOURNAL
VTODO   <--RELATED-TO-->  VJOURNAL
```

Тип связи задаётся параметром `RELTYPE` (`PARENT`, `CHILD`, `SIBLING`).
